# Unity: перемещения и приближённые головоломки

24.10.2026. Спецификация по решениям пользователя. Профессиональные головоломки — план реализации. По следующему запросу пользователя общая локация и прогулка уже созданы в `Assets/Scenes/Brewhouse.unity`; текущая реализация — `docs/game/location/`. [Макет экранов и управления](chemist-storyboard/index.html).

## Состояния

`Explore → Approaching → Closeup → Explore`. Дополнительно `Paused` хранит прежнее состояние. Отдельный автомат станции: `Empty → Loaded → Processing → Ready → Collected`. При выходе из Closeup состояние станции не сбрасывается. Процессы станций обновляются независимо от выбранной камеры.

В Explore доступны клик по полу, WASD, касание и джойстик. Approaching хранит конкретную целевую станцию. Достигнув interaction point и порога расстояния, персонаж поворачивается к оборудованию; только затем открывается Closeup. Новая команда отменяет старую цель. Ручное движение также отменяет подход. Клик вне NavMesh не перемещает персонажа через препятствие.

В Closeup отключены перемещение, выбор прохода и джойстик. UI имеет приоритет над raycast в мир. Esc / «Отойти» сохраняет параметры оборудования и возвращает обзорную камеру. Одновременно открыто одно оборудование. Пауза замораживает общую симуляцию и таймеры; скрытая вкладка WebGL включает паузу. При возвращении требуется явное продолжение.

## Компоненты

| Компонент | Ответственность |
|---|---|
| PlayerInputRouter | Одинаковые команды от клавиатуры, мыши и touch; отсечение указателя над Canvas |
| FactoryMovement | NavMeshAgent, цель от raycast по полу, manual direction от клавиш/джойстика; один источник движения за раз |
| InteractableStation | Interaction point, дистанция, допустимый предмет, Camera anchor, кнопка действия |
| InteractionCoordinator | Подход, проверка условий, блокировка ввода движения и смена игрового режима |
| CloseupCameraRig | Обзорная камера и отдельные заранее настроенные ракурсы станции; короткий переход, без свободной тряски |
| StationProcess | Время и готовность анализа независимо от ракурса; сигнал готовности над объектом |
| CarrySlot | Один физический предмет: attach к руке / разместить на станции / забрать результат |
| PuzzleController | Состояние головоломки, проверка решения и журнал исправлений |
| ShiftSession | Время, пауза, спокойный режим, протокол; скорость отдельно от правильности |

NavMesh и доступные маршруты запекать по реальной сцене. В HTML маршруты дискретные; это не замена NavMesh. Привязка персонажа к предметам и открытие приборов должны проверяться в пространстве, а не только по нажатию кнопки Canvas.

## Ввод

- ЛКМ / tap по полу: идти к доступной точке. ЛКМ / tap по оборудованию: подойти, затем приблизить. ПКМ допускается позднее как настройка; базовое действие одно, без обязательного двойного клика.
- WASD / стрелки: прямое движение в координатах обзорной камеры. E: работа с ближайшей доступной станцией. Esc: отойти из головоломки, из обзора — пауза.
- Touch: касание и небольшой джойстик — одновременно доступные способы. Джойстик не перехватывает касания мира за пределами своей области; завершение касания, отмена указателя и потеря фокуса сбрасывают направление. Справа контекстное действие.
- Прибор: кнопки на World Space Canvas или Canvas поверх крупного плана; вентиль — угол по положению указателя относительно оси. Клавиши и ползунок дают эквивалентный точный ввод. Захватывать pointer до отпускания, не терять вращение при выходе за пределы колеса.

## Камера и Canvas

Основной экран — 16:10, повышенная камера в три четверти, большая видимая площадь завода, как в предоставленной панораме. Камера следит за текущим участком без ручного вращения. Оборудование имеет свой closeup anchor; голова и тело персонажа не закрывают прибор. Reduce motion заменяет переход мгновенной сменой ракурса.

HUD: роль/четыре отметки слева, одна задача по центру, время/пауза справа. На объектах — маленькие маркеры и готовность. Остальной UI появляется контекстно. Бортовой компьютер воспринимается частью оборудования; данные синхронизированы с состоянием станции, а не отдельной демонстрационной надписью.

Кнопки ПК компактные (примерно 28–36 px при масштабе 1600×1000). На телефоне визуальный размер и зона касания задаются отдельно; уменьшать весь desktop Canvas пропорционально нельзя. Планируется landscape/fullscreen, крупный план с изменённой компоновкой. Нативная работа WebGL в мобильном браузере ещё не проверена.

## Первая вертикальная сборка

Одна доступная петля прохода, один персонаж, один переносимый образец, четыре станции. Сначала проверить `идти → подойти → открыть → покрутить → отойти` и отсутствие конфликтов ввода. Затем добавить автономное измерение, расчёт и протокол. Очередь проб и новые профессии — после проверки этого цикла.

Приёмка: нельзя взаимодействовать издалека; персонаж обходит линию; новый клик меняет маршрут; UI не задаёт команду идти; прибор продолжает работу в общем виде; перенесённая проба имеет тот же идентификатор в протоколе; пауза останавливает оба таймера; ошибка требует исправления; touch cancel не оставляет движение включённым. Проверить клавиатуру, мышь и реальный touch отдельно. Не считать HTML-проверки подтверждением Unity-сборки.
